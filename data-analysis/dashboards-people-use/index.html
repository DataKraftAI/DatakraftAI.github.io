Dashboards people actually use: one question per chart

Most companies have more dashboards than they have questions. The few that get used every week share five simple habits.

DataKraft · 5 min read

A new dashboard is usually opened often in its first week and rarely after that. Not because the data is wrong, but because nobody can tell, within a few seconds, what it is saying or what to do about it. These are the rules I follow to build dashboards that stay in use.

1. One question per chart

Write the question above each chart, as a sentence: "Are we on track for this month's revenue target?" If you cannot write the question, the chart probably should not be there. If a chart answers two questions, split it.

2. Always show a comparison

A number on its own means little. "€412k" says nothing; "€412k, 2% below target, up 3% on last month" says a lot. Every key number gets at least one comparison: target, last period or last year.

3. Agree the definitions, and show them

Half of all dashboard arguments are really definition arguments. What counts as an active customer? Are returns subtracted from revenue? Write each definition once, agree it with the owners, and put it in a small note next to the chart.

MetricDefinition (example)
Active customerPlaced at least one order in the last 90 days
Net revenueOrder value minus returns and marketplace fees, excluding VAT
Churn rateCustomers lost this month ÷ customers at the start of the month

4. Fewer charts, in a fixed order

Five to eight charts, from the most important to the least, always in the same place. People learn where to look. Anything else goes on a second page for those who need detail.

A dashboard is finished not when nothing can be added, but when nothing can be removed.

5. Give it an owner and a meeting

A dashboard without an owner slowly goes stale. A dashboard without a meeting is never discussed. The ones that last are opened at the start of a recurring meeting, with a named person who explains what changed and why.

Before you build: is this a dashboard at all?

Some questions are asked once. They need an analysis and a decision, not a permanent dashboard. Only build a dashboard for questions that come back every week or month. For the one-off ones, see start with the decision, not the data.
